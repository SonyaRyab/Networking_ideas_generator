# Транспортный уровень — генерация идей для контента

Сервис принимает запрос браузера по HTTP, передаёт его агенту, принимает манифест и сегменты ответа, имитирует потерю 10% сегментов перед Kafka и собирает полный результат. После проверки длины, SHA-256 и структуры JSON он отдаёт группы идей через Server-Sent Events. Запуск модели и интерфейс пользователя относятся к другим уровням проекта.

## Запуск

Требуются Python 3.10+, Docker с Compose и доступный по сети агентный сервис. На машине транспорта:

```powershell
cd transport
Copy-Item .env.example .env
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
docker compose up -d
```

В `.env` укажите `AGENT_BASE_URL` — адрес компьютера агента, например `http://192.168.1.12:8000`. `KAFKA_BOOTSTRAP_SERVERS` оставьте `127.0.0.1:9092`, если брокер работает на этой же машине. Убедитесь, что порт `8080` доступен компьютеру с прикладным уровнем и агенту. Запустите сервис:

`CORS_ORIGINS=*` подходит для учебной сети без авторизации. Если известен адрес веб-приложения, можно перечислить разрешённые источники через запятую, например `http://localhost:5173,http://192.168.1.10:5173`.

```powershell
python -m app
```

Сервис создаёт топик `content-idea-segments` при подключении к Kafka. При временной недоступности Kafka он повторяет подключение каждые 5 секунд. `GET http://127.0.0.1:8080/api/v1/health` показывает готовность. Swagger UI находится по адресу `http://127.0.0.1:8080/docs` и использует файл `transport.openapi.yaml`.

Для сети ZeroTier в `.env` укажите ZeroTier IP компьютера агента в `AGENT_BASE_URL`; адрес транспорта, доступный агенту, настраивается уже в конфигурации агентного уровня. Все три уровня могут храниться в одном репозитории, но запускаться на разных компьютерах.

Фронтенд из ветки `frontend` обращается к адресу из `VITE_TRANSPORT_URL` (сейчас там указан `localhost:8080`). Если браузер работает на другом компьютере, перед сборкой фронтенда задайте в его `.env` доступный браузеру адрес транспорта, например `http://<ZeroTier-IP-транспорта>:8080`. Для локальной проверки на одном компьютере текущий адрес подходит.

## Контракт

- `POST /api/v1/requests` — принять задание от интерфейса, передать агенту и вернуть `202` с `statusUrl` и `eventsUrl`.
- `GET /api/v1/requests/{messageId}` — текущее состояние и полный результат после успешной сборки.
- `GET /api/v1/requests/{messageId}/events` — SSE-события `idea_group`, `generation_completed`, `generation_error` с поддержкой `Last-Event-ID`.
- `POST /api/v1/messages/{messageId}/manifest` — зарегистрировать число сегментов, длину и SHA-256 до приёма сегментов.
- `POST /api/v1/segments` — проверить и однократно обработать сегмент; `202` подтверждает HTTP-обработку, в том числе при учебной потере.
- `POST /api/v1/messages/{messageId}/failure` — получить терминальную ошибку агента.
- `GET /api/v1/health` — готовность транспорта и Kafka.

Каждый новый запрос должен иметь новый UUID v4. Повтор того же нормализованного запроса с тем же UUID не запускает генерацию повторно. Сегменты размером до 512 байт UTF-8 поступают в Kafka только после розыгрыша потери. Повтор сегмента не разыгрывает потерю снова. Сборка проверяется раз в 3 секунды; 3 интервала без нового уникального сегмента приводят к `ASSEMBLY_TIMEOUT`. Если манифест не появился за 120 секунд, возникает `GENERATION_TIMEOUT`. Итоговые записи и SSE-журнал хранятся в памяти 15 минут. Одновременный запуск нескольких экземпляров транспорта с этим временным хранилищем не предусмотрен.

Прикладной уровень открывает EventSource по `eventsUrl` после получения `202`. После терминального события клиент закрывает EventSource. При повторном подключении браузер передаёт последний полученный `id` через `Last-Event-ID`. Постоянную историю чата транспортный уровень не хранит; состояние запроса и журнал SSE-событий имеют ограниченный срок жизни.

## Проверка без готового агента

Тесты используют подставной HTTP-ответ агента и подставную очередь Kafka. Они проверяют приём, дедупликацию, потерю, сборку, контрольную сумму и SSE-журнал без локальной LLM. Когда агент коллеги будет готов, задайте его адрес и проведите сквозной запуск трёх уровней.

```powershell
python -m unittest discover -s tests -v
```
