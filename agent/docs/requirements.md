# Соответствие агентной части РПЗ

Реализация опирается на разделы «Агентный уровень», 2.1, 2.2, требования ТЗ
к агенту и сценарии 5–6 ПМИ. Контракт дополнительно проверен по ветке
`origin/transport`, коммит `c6071a223e4ced22dc463064ea88024e39974619`.

| Требование | Реализация | Проверка |
| --- | --- | --- |
| Python, FastAPI, Uvicorn; отдельный сервис | `app/main.py`, `app/__main__.py` | HTTP API, Swagger |
| POST generate, фон и 202 | `app/main.py`, `app/store.py` | Ответ до окончания модели, задача завершается в фоне |
| UUID v4, исходное время с часовым поясом | `app/schemas.py` | Невалидные UUID/время отклоняются; метаданные сохраняются |
| Имя 1–50, тема 1–500, пожелания до 2000 | `GenerateRequest` | Граничные длины, пустые поля, Unicode |
| 5 форматов, целое число идей 10–15, default 12 | `GenerateRequest`, `app/prompts.py` | Все планы 10–15; null, bool, float, неизвестные поля отклоняются |
| Ограничение тела 64 КиБ | Потоковое чтение `parse_body` | Обычное и chunked тело |
| Локальная instruct-модель 1–7B, русский | Ollama, Qwen 3 4B Instruct Q4_K_M | Реальная модель; отчёт в `validation.md` |
| Промпт по теме, формату и пожеланиям | `app/prompts.py` | Пользовательские поля изолированы в JSON, формат имеет отдельную инструкцию |
| Пользователь не меняет служебную схему | Системный промпт, строгий JSON Schema, метаданные добавляет код | Незапланированные поля отклоняются; callback URL запрещён |
| Идея: номер, заголовок до 120, описание до 600 | `Idea`, `GenerationResult` | Пустой/длинный текст и повторные заголовки отклоняются |
| Тематические группы по 3–4 идеи | `GROUP_PLANS`, промпт и валидатор | Точные размеры и нумерация всех шести планов; непустые разные внутренние темы групп |
| Ограниченный повтор невалидного ответа | `app/ollama.py` | Коррекция JSON; исчерпание попыток даёт ошибку без сегментов |
| SHA-256 точной сериализации до отправки | `prepare_delivery` | Склейка payload совпадает с длиной и хешем манифеста |
| Манифест перед первым сегментом | `Delivery.send` | Порядок вызовов; при 409 сегменты не отправляются |
| Сегменты не более 512 байт UTF-8 | `split_utf8` | Кириллица, emoji, кавычки, границы многобайтных символов |
| Номер/число сегментов, sender и время | `Segment` | Совместимость с валидаторами транспорта |
| Последовательная отправка, пауза 100–300 мс | `Delivery.send`, default 150 мс | Порядок и паузы вызовов |
| Нет повторной отправки намеренно потерянного пакета | HTTP 202 завершает отправку сегмента | Проверка количества запросов, потери 100% в интеграционном тесте |
| Ошибка после 202 через failure | `JobStore.fail`, `Delivery.notify_failure` | Ошибка модели, дедлайн, ошибка доставки, недоступность failure endpoint |
| GET диагностики и GET health | `app/main.py` | Состояния, модель отсутствует/доступна, 404/422 |
| Идемпотентность нормализованного запроса | `JobStore.accept` | Повтор в процессе/после завершения; конфликт другого тела |
| TTL 15 минут, память текущего процесса | `JobStore.purge`, lifecycle | Удаление по TTL, отмена задач при остановке |
| Сетевые адреса через окружение, три узла | `app/config.py`, `.env.example`, Compose | Конфигурация и HTTP roundtrip с кодом транспорта |
| macOS и Windows, Docker | Dockerfile и три Compose-файла | Контейнер Python 3.12; CPU/Metal/NVIDIA варианты в README |

Семантическое соответствие теме, неповторяемость смысла и тематическая близость
не доказываются структурной проверкой JSON. Они задаются промптом и требуют
просмотра результатов. Код проверяет повторение нормализованных заголовков,
но не заявляет автоматическую оценку качества или защиту от любой prompt injection.

## Уточнения документа для общей интеграции

1. В ТЗ говорится о заголовке каждой тематической группы. В разделах 2.1 и в
   `transport/app/schemas.py` группа имеет только `groupNumber` и `ideas`,
   `extra=forbid` запрещает поле заголовка. Агент реализует действующий wire-контракт. Внутреннее поле модели `theme`
   помогает планировать разные тематические группы, но не входит в wire-ответ.
   Для отображения тематических заголовков нужно согласованно добавить поле
   на транспорте, в его OpenAPI/SSE и frontend, затем в схеме результата агента.
2. ТЗ перечисляет Windows для агента, РСА — macOS 13+. Реализация переносима;
   актуальная нативная Ollama требует macOS 14+. Для M5 используется нативная
   модель с Metal, а сервис агента можно контейнеризировать. Docker Desktop на Mac
   не предоставляет GPU Ollama-контейнеру.
3. Отправка групп в интерфейс происходит только после полной сборки и проверки
   транспорта. Агент не выдаёт сырые токены через SSE. Группы и сетевые сегменты
   имеют разное назначение и разное количество.
4. Завершение агента означает отправку сегментов, а не их сборку на транспорте.
   При потере 10% корректен транспортный `ASSEMBLY_TIMEOUT` даже после агентного
   `completed`. Повторять все подтверждённые сегменты ради успеха нельзя.
5. РПЗ содержит чужие фрагменты в руководстве пользователя (поиск архивного
   документа), упоминание авторизации при фактическом вводе имени и старые пути
   `/api/requests` вместо `/api/v1/requests`. Это относится к общему документу и
   прикладному уровню; агент использует версионированные пути актуального транспорта.

Исходный DOCX не изменялся. Здесь зафиксированы требования и расхождения для
последующей общей правки РПЗ исполнителями трёх уровней.
