# Проверка агентного сервиса

Проверки выполнены 22 ноября 2026 года на MacBook Air с Apple M5 и 16 ГБ RAM.
Нативная Ollama 0.40.17 использовала Metal, контекст 4096 токенов, параллелизм 1.
Агент проверялся на Python 3.12 и в Linux ARM64 контейнере Python 3.12.

## Автоматизированные проверки

Команда из `agent/`:

```sh
TRANSPORT_SOURCE_DIR=/tmp/networking-transport-source/transport ../.venv/bin/python -m pytest -q
```

Результат: **72 passed**. Использован код `origin/transport` на коммите
`c6071a223e4ced22dc463064ea88024e39974619`, без изменения транспортной ветки.
При отсутствии исходников транспорта три интеграционных сценария пропускаются;
остальные проверки выполняются самостоятельно.

Проверены границы входных данных, ошибки HTTP, UUID и RFC3339, Unicode, потоковый
лимит тела, идемпотентность, конфликт запросов, независимые одновременные задания,
ограничение очереди, общий дедлайн, повтор невалидного JSON, ошибки Ollama,
порядок манифеста/сегментов, SHA-256, все планы 10–15 идей и сетевые повторы.
Грамматика модели дополнительно проверена как JSON Schema: для каждого числа
идей она требует точные размеры групп и номера каждого элемента.
Внутренние темы групп должны быть непустыми и различаться.

Интеграционные сценарии используют настоящий HTTP API, схемы и сборщик транспорта,
подставную Ollama и очередь в памяти вместо Kafka:

- Потери 0%: сборка результата, три `idea_group`, затем `generation_completed`.
- Потери 100%: агент подтверждает отправку, транспорт выдаёт `ASSEMBLY_TIMEOUT`
  и `generation_error` без частичного результата.
- Ollama возвращает 404: транспорт получает `MODEL_UNAVAILABLE` через `/failure`.

Также прошли `ruff check`, `ruff format --check`, `pip check`, проверка синтаксиса
для Python 3.10, валидация OpenAPI 3.0.3 и разбор всех трёх Compose-конфигураций.
TestClient выдаёт одно предупреждение о будущем переходе Starlette с httpx на
httpx2; на результат проверок оно не влияет.

## Реальная модель и контейнер

По итогам просмотра русского текста выбрана `qwen3:4b-instruct-2507-q4_K_M`,
веса около 2,5 ГБ. Qwen 2.5 3B быстрее, но в просмотренных примерах чаще повторяла
идеи и допускала неудачные формулировки. Это оценка конкретных примеров, не
формальный сравнительный бенчмарк. Ollama `/api/ps` для выбранной модели показала
3 181 631 242 байта (около 3,2 ГБ) в GPU при контексте 4096 токенов.

Следующие замеры включают генерацию и отправку сегментов с паузами 150 мс.
Это отдельные наблюдения при конкретной нагрузке ноутбука, а не гарантированная
скорость для любых запросов и компьютеров.

В контейнерной проверке Docker Compose собрал образ, health вернул 200,
агент обратился к нативной Ollama через `host.docker.internal`, а манифест и все
сегменты поступили временному HTTP-приёмнику на хосте. Сборка приёмником
подтвердила размер, SHA-256, UTF-8 и схему GenerationResult.

Для проверки использовалась переносимая Ollama из `/tmp/networking-ollama/`
и модели в `/tmp/networking-ollama-models/`, порт 11435. Это временная тестовая
среда; стандартный запуск с установленной Ollama использует порт 11434.

Подробные локальные отчёты со сгенерированными идеями находятся в `agent/reports/`.
Они исключены из Git. Команда для воспроизведения теста реальной модели приведена
в README; Docker-проверка использовала отдельные временные порты 18000/18080.

Полный запуск на трёх физических компьютерах с настоящей Kafka и frontend не
проводился. Windows и NVIDIA-конфигурация подготовлены, но на Windows не запускались.
Структурная проверка не доказывает качество текста, истинность утверждений или
семантическую уникальность идей; перед публикацией идеи просматривает пользователь.
